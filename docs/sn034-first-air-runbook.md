# SN-034 — первый воздушный файл (Laptop → Phone, 30 см)

**Статус:** подготовлено, передача через воздух не выполнялась  
**Дата подготовки:** 2026-11-04  
**Связанные:** `docs/acoustic-file-transfer.md`, `docs/sn028-next-plan.md`,
`TASK_BOARD.md` (SN-034)

Это отдельный тест файлового слоя. Он **не входит** в статистику SN-028 и не
меняет её пороги. Успешный файловый round-trip через WAV, PLAY или запись без
проверки SHA-256 не считается передачей через воздух.

## 2. Что нужно перед прогоном

1. Подключить телефон по USB или установить текущий APK вручную.
2. Убедиться, что встроенный микрофон ноутбука не используется: направление
   только Laptop → Phone. Обратное направление остаётся
   `PENDING EXTERNAL MICROPHONE`.
3. Открыть на ноутбуке WAV и выбрать динамик ноутбука. Громкость зафиксировать
   и записать в метаданные; внутри прогона её не менять.
4. На телефоне открыть Audio Lab → «Файлы через звук», профиль
   `data-audible`, запись **15 с**.
5. Расстояние между динамиком ноутбука и микрофоном телефона — 30 см по
   рулетке. Записать модель телефона, модель ноутбука и помещение.

## 3. Порядок прогона

1. Запустить запись 15 с на телефоне.
2. Сразу воспроизвести WAV один раз.
3. Дождаться конца записи; вручную не останавливать, иначе запись считается
   отменённой.
4. Экспортировать с телефона принятый файл и JSON-отчёт (`WAV` + `.json`).
5. Положить артефакты в `reports/` и разобрать WAV независимо:

   ```powershell
   cd acoustic-lab
   python file_transfer.py receive `
     --wav <экспортированный.wav> `
     --out-dir results\sn034-first-air\air-01
   ```

## 4. Критерий успеха

- на телефоне `result: ok`, имя `sn034-air-01.json`, размер 43 байта;
- фактический SHA-256 равен
  `596343205aae63f0918b4b0ce042fa7e60ac7d308e819906fdac9d1535119f5a`;
- Python независимо собирает файл из экспортированного WAV с тем же SHA-256;
- в отчёте есть дистанция, громкость, модели устройств, профиль, дата и время.

Если SHA-256 не совпал или чанк потерян, попытка фиксируется как неуспешная.
Пороги и профиль не меняются. Повтор разрешён только при сбое экспорта, а не
для подмены неудачного приёма.

## 5. Ограничения

- один файл 0…8192 байт, без ACK и докачки;
- SHA-256 проверяет целостность, но не аутентифицирует отправителя;
- CRC-16 не аутентификация; SCNP/AEAD ещё нет, личные данные не передавать;
- результат одного файла не заменяет серию SN-028 10/10 на 30 см.
