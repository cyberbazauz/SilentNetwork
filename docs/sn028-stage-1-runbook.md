# SN-028 — runbook серии 30 см (Laptop → Phone)

**Дата:** 2026-11-03  
**Статус:** готов к выполнению, параметры утверждены Product Owner  
**Связанные:** `docs/sn028-physical-test-protocol.md`,
`docs/sn028-next-plan.md`, `acoustic-lab/results/sn028-first-contact.md`

Цель: получить серию из 10 физических попыток на 30 см с артефактами WAV/JSON
и метаданными, затем вынести формальный вердикт. Порог: **10/10** точных
текстов при CRC OK.

## 0. Что уже известно

| Параметр | Значение |
|---|---|
| Ноутбук | HP OMEN by HP Gaming Laptop 16-n0xxx |
| ОС ноутбука | Windows 11 Pro, build 26200 |
| Динамик Windows | MME `[3] Speaker (Realtek(R) Audio)` |
| Профиль | `data-audible`, 48 000 Гц, 1200/2200 Гц, 300 бод |
| Текст кадра | M1–M3 по кругу (см. §2) |
| Запись Android | 10 с, автоматическое окончание |
| Микрофон ноутбука | нерабочий, в этой серии не используется |

Неизвестно и заполняется вручную: модель телефона, версия Android, громкость
Windows и Android, помещение, фоновый шум.

## 1. Подготовка (один раз перед серией)

1. Тихая комната. Телефон не на мягкой поверхности: не на кровати, полотенце
   или пледе.
2. Рулеткой отмерить **30 см** от решётки динамика ноутбука до микрофона
   телефона. Оба устройства на одной высоте, динамик направлен на микрофон.
3. Зафиксировать положение так, чтобы его нельзя было случайно сдвинуть.
4. Выставить громкость Windows и Android **один раз**. Записать значения.
5. Windows: запустить `dist\SilentNetwork-Desktop.exe`.
6. Android: установить `dist\SilentNetwork-Android.apk`, выдать `RECORD_AUDIO`.
7. Контрольный тон: Windows → 1 кГц, Android → запись. Убедиться, что сигнал
   заметно выше фона и **нет клиппинга** (индикатор Android). Если клиппинг —
   уменьшить громкость до начала серии и заново записать значения.
8. Заполнить шапку метаданных (§3). Время серии — местное UTC+5.

Если громкость или положение пришлось изменить — это делается **до** первой
попытки. Внутри серии они не меняются.

## 4. Одна попытка — точный порядок

1. Windows: раздел «Передача данных», профиль `data-audible`, ввести текст
   текущей попытки.
2. Windows: нажать «Создать WAV» (только файл, без звука).
3. Android: раздел «Передача данных», профиль `data-audible`, длительность
   записи **10 с**. Нажать «Записать» и разрешить запись.
4. Windows: сразу нажать «Воспроизвести» и подтвердить PLAY. Кадр начинается
   примерно через 2.4 с записи, поэтому играть нужно без паузы.
5. Android: **не нажимать «Стоп»**. Дождаться автоматического окончания 10 с —
   декодирование запустится само. «Стоп» отменяет запись.
6. Android: записать с экрана результат: текст, CRC, преамбула, клиппинг.
7. Android: экспортировать WAV и JSON, переименовать по шаблону из §2.
8. Сразу внести строку в таблицу §5.

Между попытками менять только текст. Не менять: профиль, громкость, положение
телефона, расстояние, приложение.

## 6. Разбор серии

Сложить все WAV и JSON в один каталог, например
`C:\Users\<user>\Documents\sn028-30cm`, и выполнить:

```powershell
cd C:\Projects\SilentNetwork\acoustic-lab
python sn028_series.py --dir C:\Users\<user>\Documents\sn028-30cm --distance 30cm
```

Анализатор:
- независимо декодирует каждый WAV Python-приёмником;
- сверяет CRC и текст с M1–M3 по имени файла;
- считает RMS, пик, клиппинг, преамбулу;
- пишет CSV, JSON и Markdown в `acoustic-lab/results/sn028/series/`;
- возвращает код 0 при PASS, 2 при FAIL, 3 при INCOMPLETE.

PASS возможен только при 10/10. Если записей меньше 10 — вердикт `INCOMPLETE`,
и это не PASS.

## 7. Если попытка не удалась

Разрешено:

- довести серию до конца, ничего не меняя;
- зафиксировать фактическую причину: `signal_not_found`, `crc_mismatch`,
  `incomplete_frame`, клиппинг, обрезанная запись, ошибка человека;
- после завершения серии провести **отдельную** диагностическую серию и
  опубликовать её отдельно.

Запрещено:

- удалять или переименовывать неудачную попытку, чтобы «заменить» её;
- менять громкость, положение или профиль внутри серии;
- менять пороги PASS, Frame v1, CRC или payload;
- объявлять PASS по 9/10, по одной удачной попытке или по файлу из
  `reports/`.

Если попытка сорвалась по ошибке человека (забыли нажать PLAY, нажали «Стоп»),
она помечается `technical_invalid` с объяснением. Чтобы получить 10 зачётных
попыток, можно выполнить дополнительные, но исходная запись и пометка
сохраняются.

## 8. Что предоставить Agent 1

1. Каталог с 10 WAV и 10 JSON (или ссылку на него).
2. Заполненную шапку метаданных из §3.
3. Таблицу §5 с результатами с экрана Android.
4. Дату и время серии.

Agent 1 независимо проверит файлы и опубликует результат в
`acoustic-lab/results/sn028-stage-1-30cm.md` со статусом PASS/FAIL и
ограничениями. Только после этого серия считается оформленной.

## 9. Ограничения

- Тест доказывает передачу на конкретном ноутбуке, телефоне, расстоянии и
  громкости. Он не доказывает дальность 50–100 м и работу на любых устройствах.
- CRC-16 не является аутентификацией. Секреты и личные данные не передаются.
- Направление Phone → Laptop остаётся `PENDING EXTERNAL MICROPHONE` и в эту
  серию не входит.
