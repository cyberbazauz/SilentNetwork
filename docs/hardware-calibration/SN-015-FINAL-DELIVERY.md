**Дата:** 2026-11-02

> **Важно.** Этот документ описывает **ручной** физический тест. Приложение
> не управляет телефоном по Wi-Fi, Bluetooth, USB или сотовой сети и не
> использует их как транспорт данных. Единственный канал — динамик ноутбука →
> воздух → микрофон телефона. Все проверки при подготовке поставки были
> синтетическими: звук не воспроизводился, микрофон не записывал.

## 2. Требования

### Ноутбук

- Windows 10/11 x64.
- Python 3.10+ (проверено на 3.12.10) с компонентом **tcl/tk and IDLE**.
- Свободный доступ к настройкам громкости Windows.
- Рабочий динамик (встроенный или подключённый).

### Телефон

- Android 8.0+ (`minSdk 26`), `targetSdk 34`.
- Встроенный микрофон.
- Разрешение на запись звука.
- 50–100 МБ свободного места для WAV.

## 3. Установка Android APK

APK: `dist/SilentNetwork-Android.apk`  
Package name: `org.silentnetwork.app.debug`  
Version name: `0.1.0-alpha`

### Вариант A — через ADB (предпочтительно)

```powershell
adb devices
adb install -r "dist\SilentNetwork-Android.apk"
```

Ожидаемый ответ: `Success`.

### Вариант B — вручную

1. Скопируйте APK на телефон (USB, файловый менеджер).
2. Откройте файл на телефоне.
3. Разрешите установку из этого источника, если Android попросит.
4. Установите приложение **SilentNetwork**.

> APK подписан стандартным debug-ключом. Это не production-подпись. Не
> публикуйте его в магазинах и не считайте защищённой сборкой.

После установки откройте приложение и перейдите на вкладку **Audio Lab**.
При первом запуске записи Android запросит доступ к микрофону — разрешите
его. Приложение показывает фактический маршрут и фактический sample rate.

## 4. Запуск Windows-приложения

Откройте PowerShell в каталоге поставки:

```powershell
cd "dist\SilentNetwork-Desktop"
python -m pip install -r requirements-desktop.txt
```

Проверка без звука (рекомендуется перед первым запуском):

```powershell
.\run_desktop.bat --smoke-test
```

Ожидаемый вывод:

```text
GUI smoke test OK: hardware_test=False, play_enabled=False, results_dir=...
```

Обычный запуск (PLAY доступен после создания сигнала):

```powershell
.\run_desktop.bat
```

Совместимый запуск с прежним флагом:

```powershell
.\run_desktop.bat --hardware-test
```

> `--hardware-test` больше не требуется и не начинает воспроизведение сам.
> Кнопка **PLAY** доступна после генерации WAV, а перед каждым PLAY приложение
> запрашивает подтверждение. Системный динамик выбирается автоматически.

Окно приложения состоит из трёх основных областей:

- **«Динамик ноутбука»** — выбранное устройство и раскрываемый список;
- **«Отправить тестовый сигнал»** — параметры, создание WAV, PLAY/STOP;
- **«Проверить запись телефона»** — импорт записи и результат анализа.

## 5. Выбор динамика ноутбука

1. Динамик ноутбука выбирается автоматически при запуске.
2. При необходимости нажмите **«Обновить список»**, раскройте **«Выбрать
   устройство»** и выберите другую строку (например, `Speakers`, `Realtek`,
   `Headphones`).
3. Нажмите **«Проверить 48/44.1 кГц»**. Это проверяет поддержку форматов, но
   не открывает поток.
4. Если устройство не появилось, проверьте, что Windows видит динамики, и
   нажмите «Обновить список» ещё раз.

Не выбирайте устройства ввода (микрофоны) и виртуальные кабели, если не
понимаете их назначение.

## 6. Подготовка Receiver на телефоне

1. Откройте **Audio Lab**.
2. В блоке **B. LAPTOP → PHONE RECEIVER** заполните:
   - **TEST ID** — можно оставить автоматический;
   - **Ожидаемая частота** — частота, которую будет играть ноутбук
     (для первого теста `1000`);
   - **Длительность записи** — `10 сек` (первый тест).
3. Убедитесь, что статус — `READY`, а маршрут показывает встроенный микрофон.
4. Не включайте громкую связь, диктофон и другие приложения, использующие
   микрофон.
5. Положите телефон рядом с ноутбуком, микрофоном к динамику. Начните с
   расстояния 20–30 см.

> Не закрывайте приложение во время записи. Android может остановить
> фоновую запись.

## 7. Первый тест: 1 кГц

Цель — проверить весь тракт на заведомо слышимой частоте, где нет вопросов
к аппаратной поддержке динамика и микрофона.

### 7.1. Сгенерировать сигнал на Windows

1. Запустите Windows-приложение.
2. Проверьте автоматически выбранный динамик ноутбука (раздел 5).
3. В области **«Отправить тестовый сигнал»** установите:
   - **Частота, Гц:** `1000`;
   - **Sample rate, Гц:** `48000` (в «Дополнительных настройках»);
   - **Длительность, с:** `3.0`;
   - **Амплитуда (0..1):** `0.10` (в «Дополнительных настройках»);
   - **Тишина до, мс:** `500` (в «Дополнительных настройках»);
   - **Тишина после, мс:** `500` (в «Дополнительных настройках»).
4. Нажмите **«Создать сигнал»**.
5. Убедитесь, что появилось имя WAV и путь к папке результатов. Звук на этом
   шаге не воспроизводится.

WAV и JSON сохраняются в
`acoustic-lab/results/hardware_calibration/` (при запуске из `dist` —
`dist/SilentNetwork-Desktop/results/hardware_calibration/`).

### 7.2. Начать запись на телефоне

1. На телефоне нажмите **«НАЧАТЬ ЗАПИСЬ»**.
2. Убедитесь, что статус сменился на `RECORDING` и идёт отсчёт секунд.

### 7.3. Воспроизвести тон

1. Сразу после начала записи нажмите **PLAY** в Windows-приложении.
2. Подтвердите воспроизведение в диалоге.
3. Дождитесь окончания тона. Приложение покажет статус и путь к playback
   JSON. Этот JSON создаётся только после фактической попытки PLAY.

### 7.4. Остановить запись

1. Дождитесь автоматического окончания записи (10 секунд) или нажмите
   **«ОСТАНОВИТЬ ЗАПИСЬ»**.
2. Статус должен стать `RECORDING COMPLETE`.
3. Нажмите **«Передать в анализатор»**. Приложение покажет RMS, Peak, dBFS,
   клиппинг, DC offset и спектральные пики.
4. Проверьте **Expected vs Detected**: для 1 кГц обнаруженная частота должна
   быть близка к 1000 Гц.

### 7.5. Экспортировать WAV и JSON

1. Нажмите **«Экспорт записи WAV»**. Android откроет системный диалог
   сохранения; выберите папку `Download` и запомните имя файла
   (`sn015_<test_id>_rx.wav`).
2. Нажмите **«Экспорт JSON-отчёта»**, сохраните
   `sn015_<test_id>_result.json` в ту же папку.
3. Перенесите оба файла на ноутбук: USB-кабелем (режим передачи файлов),
   через файловый менеджер или облако. Облако допустимо только для переноса
   **файлов результата**, не для передачи сигнала в реальном времени.

### 7.6. Импортировать WAV в Windows

1. В Windows-приложении в блоке **D. PHONE WAV → ANALYSIS** установите
   **Expected frequency, Гц:** `1000`.
2. Нажмите **«Импорт WAV с телефона»** и выберите
   `sn015_<test_id>_rx.wav`.
3. Приложение скопирует файл в папку результатов и создаст:
   - `*.analysis.json` — полный анализ;
   - `*.analysis.csv` — метрики;
   - `*.psd.png` — спектр;
   - `*.spectrogram.png` — спектрограмма.
4. В текстовой панели проверьте:
   - `sample_rate_hz` — должен совпадать с фактическим sample rate телефона;
   - `samples` и `duration_s` — соответствуют длительности записи;
   - RMS/Peak dBFS — не `-inf` и не около `0 dBFS`;
   - `clipping_count` — желательно `0`;
   - `detected_frequency_hz` — рядом с ожидаемой частотой;
   - `frequency_offset_hz` — знаковая разница.

Кнопки **«Открыть PSD PNG»** и **«Открыть спектрограмму»** открывают
сохранённые графики.

> Windows-приложение **не импортирует Android JSON автоматически**. JSON
> телефона используется как отчёт о том, что записал и посчитал телефон;
> ожидаемая частота вводится в Windows вручную. Это сознательное ограничение
> первой поставки, а не скрытая функция.

### 7.7. Как читать результат

Для первого теста достаточно качественной картины:

- сигнал виден в PSD заметно выше шумового пола;
- клиппинга нет;
- обнаруженная частота близка к ожидаемой;
- WAV с телефона открывается без ошибок формата.

Конкретные пороги PASS/FAIL для M0 утверждает Product Owner. Приложение
**не выставляет автоматический PASS** и не заменяет решение человека.
Ширина поиска пика в Windows — ±300 Гц вокруг ожидаемой частоты; если пик не
найден, в отчёте будет предупреждение.

## 8. Переход к 18–19 кГц

Диапазон 18–19 кГц — **экспериментальная гипотеза M0**, а не гарантия.
Некоторые динамики и микрофоны его не воспроизводят или не принимают.

Рекомендуемая последовательность (каждый шаг — отдельная запись и отдельный
анализ):

| Шаг | Частота | Что проверяется |
|---|---|---|
| 1 | 1 кГц | весь тракт, слышимый контроль |
| 2 | 8 кГц | середина полосы |
| 3 | 15 кГц | верхняя слышимая граница у многих взрослых |
| 4 | 16 кГц | граница слышимости |
| 5 | 17 кГц | подход к M0 |
| 6 | 18 кГц | нижняя граница M0 |
| 7 | 18.5 кГц | центр M0 |
| 8 | 19 кГц | верхняя граница M0 |

Для каждого шага:

1. На Windows выберите ту же частоту и создайте WAV.
2. На телефоне выставьте ту же **Ожидаемую частоту**.
3. Запишите 10 секунд, воспроизведите тон, остановите запись.
4. Проанализируйте на телефоне и экспортируйте WAV/JSON.
5. Импортируйте WAV в Windows с той же Expected frequency.
6. Сохраните результаты; подписывайте файлы частотой и расстоянием.

Если на 18–19 кГц сигнал не обнаружен, это **отрицательный результат
измерения**, а не ошибка приложения. Зафиксируйте его честно: частота,
устройство, расстояние, громкость Windows, наличие клиппинга. Не поднимайте
громкость до искажений и не используйте эквалайзеры/усиления.
