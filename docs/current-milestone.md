## 1. Цель M0

Создать минимальный, воспроизводимый и проверяемый фундамент SilentNetwork Acoustic Lab:

1. репозиторий под версионным контролем с честным `README` и актуальными документами;
2. детерминированный BFSK-модулятор и демодулятор, работающий в **файловом** канале;
3. измеритель BER/PER на **смоделированном** канале с сохранением воспроизводимых результатов;
4. инструменты сканирования реального аудиотракта (устройства, форматы, фоновый шум, спектр);
5. тесты, включая негативные сценарии, и отчёт с фактическими числами.

**Ключевое ограничение:** M0 **не доказывает** передачу через воздух. Успешный M0 означает «модем корректен в идеальном и смоделированном канале», а не «SilentNetwork работает по воздуху».

---

## 2. Почему именно такой milestone

- В репозитории нет кода (см. аудит SN-001), поэтому начинать с mesh, SCNP или криптографии нельзя: нечего защищать и не на чем передавать.
- Architecture v1.0 §14 прямо требует сначала подтвердить физический канал инструментами Acoustic Lab.
- Разделение «файловый канал → смоделированный канал → реальный воздух» не позволяет выдать unit-тест за акустическую передачу.
- M0 даёт измеримую базу для сравнения BFSK/MFSK/OFDM в следующих этапах.

acoustic-lab/

- FEC (Reed–Solomon/LDPC) — вне M0, решение по результатам BER.

### 5.1 M0-4: методика измерения фонового шума

Решение Product Owner от 2026-11-01: из записи только фона SNR не вычисляется. Сохраняются и фиксируются:

| Величина | Метод | Где в отчёте |
|---|---|---|
| RMS | `sqrt(mean(x²))` по всей записи | `analysis.level.rms_dbfs` / `rms_linear` |
| Peak level | `max(abs(x))` | `analysis.level.peak_dbfs` / `peak_linear` |
| Crest factor | `peak_dBFS − RMS_dBFS` | `analysis.level.crest_factor_db` |
| Noise floor | 10-й процентиль RMS неперекрывающихся кадров по 100 мс; устойчив к коротким выбросам, не равен минимуму | `analysis.noise_floor` |
| PSD | `scipy.signal.welch`, окно Hann, `nperseg=8192`, `noverlap=4096`, `detrend='constant'`, `scaling='density'`; разрешение 5.86 Гц при 48 кГц | `analysis.psd`, `*.psd.csv` |
| Frequency spectrum | PSD в dBFS/Гц + график `semilogx` с отметками 16/18/20/22 кГц | `*.spectrum.png` |
| Clipping | число отсчётов с `|x| ≥ 0.999`, их доля и максимальная непрерывная серия | `analysis.clipping` |
| Полосы | интеграл PSD по 20–1000, 1–4, 4–8, 8–12, 12–16, 16–18, 18–20, 20–22 кГц и 22 кГц–Найквист | `analysis.bands` |

Ограничения методики, которые нельзя скрывать в отчёте:

1. Уровни зависят от усиления микрофона и обработки Windows (AGC, шумоподавление, «улучшения»); это свойство тракта, а не сигнала.
2. Список форматов драйвера не доказывает физическую работу на 16–22 кГц: MME, например, принимает 192 кГц для устройства, чей WDM-KS режим ограничен 48 кГц (наблюдение SN-010), то есть возможно передискретизирование.
3. Шумовой пол — статистика за один сеанс; он не характеризует другие часы и помещения.
4. SNR появится только вместе с известным тестовым сигналом и отдельной документированной методикой (SN-011/SN-013).

## 7. Тестовый план (команды, которые должны реально запускаться)

```powershell
python -m pytest acoustic-lab/tests -q
python acoustic-lab/scanner.py --list --out acoustic-lab/results/devices.json
python acoustic-lab/scanner.py --capture 10 --out acoustic-lab/results/noise.wav
python acoustic-lab/transmitter.py --message "SILENTNETWORK" --out acoustic-lab/results/tx.wav
python acoustic-lab/receiver.py --in acoustic-lab/results/tx.wav --out acoustic-lab/results/rx.txt
python acoustic-lab/benchmark.py --snr 0,5,10,15,20 --trials 100 --out acoustic-lab/results/ber.csv
```

Ожидаемое поведение:

- `receiver.py` на собственном WAV возвращает исходное сообщение и печатает `BER=0`;
- `benchmark.py` пишет CSV и PNG и печатает таблицу фактических BER/PER;
- при неверном формате WAV или неизвестном профиле — понятная ошибка и ненулевой код возврата.

## 8. Артефакты и доказательства

Сохраняются в `acoustic-lab/results/` (вне git, кроме итогового отчёта):

- `devices.json` — перечень устройств и форматов;
- `noise.wav`, `noise-spectrum.png` — фон и спектр;
- `tx.wav`, `rx.txt` — файловый round-trip;
- `ber.csv`, `ber.png` — фактические кривые;
- `M0-report.md` — сводный отчёт с командами и числами.

Каждый отчёт обязан содержать: версию Python и пакетов, параметры профиля, seed, дату, имя машины и аудиоустройства.
