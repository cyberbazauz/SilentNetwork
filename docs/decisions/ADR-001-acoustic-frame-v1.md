# ADR-001: кадр и BFSK-модуляция Acoustic Lab v1

- **Статус:** принято для SN-011
- **Дата:** 2026-11-01
- **Автор:** Agent 1
- **Область:** `acoustic-lab/`, только файловый канал L0
- **Связанные задачи:** SN-011 (реализация), SN-021 (приёмник), SN-013 (benchmark)

## 1. Контекст

Передатчику нужен формат, по которому приёмник сможет:

1. найти начало передачи без внешней синхронизации;
2. узнать версию формата и длину payload;
3. проверить, что принят именно этот кадр, а не случайный шум;
4. отделить повреждённый кадр от корректного.

Формат SCNP для этого не подходит: SCNP — сетевой протокол с криптографией,
которого ещё нет. Кадр Acoustic Lab — уровень PHY, он не заменяет SCNP и не
содержит идентичности, ключей или подтверждения доставки.

## 2. Решение

### 2.1 Раскладка кадра

Биты передаются старшим битом вперёд. Все многобайтовые поля — big-endian.

| Поле | Биты | Значение |
|---|---:|---|
| Преамбула | 32 | `1010…10` — 16 периодов |
| Синхрослово | 16 | `0x1ACF` |
| Версия | 8 | `0x01` |
| Длина payload | 16 | число байт, big-endian |
| Payload | 8·N | произвольные байты, N = 1…512 |
| CRC-16 | 16 | CRC-16/CCITT-FALSE по версии, длине и payload |

Служебная часть — 88 бит. Полный кадр — `88 + 8·N` бит. CRC **не** включает
преамбулу и синхрослово: они нужны для поиска, а не для целостности данных.

### 2.2 CRC

CRC-16/CCITT-FALSE: полином `0x1021`, начальное значение `0xFFFF`, без
отражения входа и выхода, без финального XOR. Проверочный вектор:
`crc16_ccitt(b"123456789") == 0x29B1`.

CRC обнаруживает случайные ошибки передачи. Он **не является**
аутентификацией: подмена payload и пересчёт CRC возможны без секрета. Защита
от подмены появится только на уровне AEAD и не входит в M0.

### 2.3 Модуляция

- Непрерывная по фазе BFSK (CPFSK): фаза не сбрасывается на границе символа.
- Один бит — один символ: `1 → mark_hz`, `0 → space_hz`.
- Частота дискретизации и частоты берутся из `BfskProfile`; профиль обязан
  проходить валидацию `config.py`.
- Число отсчётов — ровно `bits × samples_per_symbol`. Никакого padding и
  округления длительности.
- Начальная фаза по умолчанию `0`, но может быть задана вызывающей стороной.

### 2.4 Рампы

По умолчанию применяется линейное нарастание и спад 5 мс, чтобы не подавать
динамику и АЦП щелчок. Рампа не меняет число отсчётов; при коротком сигнале
она укорачивается до половины длины. `--ramp-ms 0` отключает рампу, и это
должно фиксироваться в отчёте вместе с результатом.

### 2.5 Детерминизм

Одинаковые `payload`, профиль и `ramp_ms` дают одинаковые PCM и WAV на одной
платформе и версиях библиотек. В реализации нет случайных чисел, времени и
зависимости от состояния процесса. SHA-256 считается по PCM (без заголовка
WAV) и по полному файлу WAV.

Побитовая идентичность между разными ОС **не гарантируется**: `np.sin`/libm
могут отличаться в последнем разряде. Это ограничение фиксируется в отчётах,
а не скрывается.

## 3. Альтернативы

| Вариант | Почему не выбран сейчас |
|---|---|
| Начать с SCNP-пакета | SCNP ещё не специфицирован; PHY должен проверяться отдельно |
| CRC-32 | Для кадра ≤ 520 байт хватает CRC-16; CRC-32 не даёт аутентификации |
| Разрыв фазы на каждом символе | Проще, но шире спектр и больше щелчков; CPFSK лучше для реального тракта |
| Манчестерское кодирование | Удваивает полосу; вернуть можно после измерений BER |
| Прямоугольная огибающая без рампы | Щелчки и внеполосные составляющие на старте/финише |

## 4. Последствия

- Приёмник SN-021 обязан искать преамбулу и `0x1ACF`, проверять версию, длину
  и CRC, а не доверять первому совпадению.
- Любое изменение раскладки требует новой версии, тестовых векторов и
  обновления этого ADR.
- `CRC-16` нельзя описывать как защиту от подмены или «шифрование».
- Детерминизм проверяется тестом из 20 запусков и фиксируется в отчёте.
